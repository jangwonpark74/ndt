# Samsung CongitV NDT · Toronto 3D

A city-wide Toronto map combining MapLibre GL JS, Three.js and OpenStreetMap-derived vector tiles. The viewer loads map and elevation tiles as you move around Toronto and beyond; it does not use F4 Map assets or endpoints.

The project identifier is `toronto-ndt`. This directory contains the viewer, its data preparation scripts and its tests.

## Run locally

Run the following commands from the workspace root, one directory above `ndt/`. Install [uv](https://docs.astral.sh/uv/getting-started/installation/) and GNU Make. uv manages a local Python environment (the project's current Python requirement is in the root `pyproject.toml`); the viewer has no Python package dependencies. The map and terrain tile services require an internet connection.

```sh
make setup
make run
```

`make setup` runs `uv sync --locked`; `make run` uses `uv run --locked` and creates the environment automatically if needed. Open <http://127.0.0.1:5179>; stop the server with Ctrl+C. To use a different port, run `make run PORT=5180`. The server binds to the local machine by default; `HOST` can be overridden when network access is intended. The Makefile uses `.cache/uv` by default; override `UV_CACHE_DIR` if preferred.

If you moved or renamed the project and use the virtual environment's activation scripts, recreate the environment with `uv venv --clear` followed by `make setup`; activation scripts contain absolute paths.

Drag to pan, right-drag to rotate, and scroll to zoom. The camera controls also provide zoom, tilt, rotation, a north reset and a return to the city overview; they can be used with a keyboard or touch. Use the region and project shortcuts in the left sidebar to navigate, or submit a location search in the header and choose a result. Search sends the query and current map center to the [Photon public demo service](https://github.com/komoot/photon#demo-server), which may be unavailable or rate-limited; it uses OpenStreetMap data. Click a visible feature to mark it on the map. Open Map Settings in the sidebar to toggle buildings, streets, trees, terrain and street details independently. The illustrative light comes from the southeast; optional building shadows project away from it and are off by default. MapLibre GL JS and Three.js are bundled; fonts load from Google Fonts when available.

The Network sidebar shows ISED-reported sites on the OSM map. **TELUS sites** are teal for indoor, purple for outdoor and grey for mixed, underground or unspecified locations. **Bell outdoor** locations are orange and can be switched independently. Bell sites are shown as shared-network context; TELUS use of a particular Bell site is not established by the ISED licence alone. Select a marker or nearby item for the licensee, record count, reported technologies, site type and antenna height. Records at identical coordinates share one marker per licensee.

Select a location to see its reported site description, coordinates and available ISED site identifiers. Expand **Cell and antenna records** for TELUS or **Reported directional bearings** for Bell to inspect the published radio attributes. A ring indicates that all TELUS records at that location are non-directional. At zoom 14 and closer, arrows point along the distinct reported directional TX azimuths for TELUS or Bell. At all zoom levels, Bell outdoor locations with exactly three bearings and valid beamwidths automatically display colored planning fans for bearings with usable frequencies; toggle **Sector fans** to hide them. Selecting a site is optional and shows its individual radius estimates. Each fan uses the widest reported beamwidth for its bearing, enlarged to at least 15° for visibility. Colors indicate bearing order, not a cell ID or technology. The 783 TELUS records in this extract are non-directional; 865 Bell outdoor coordinate pairs have valid directional bearings, including 454 with exactly three. A bearing can group several radio records and does not by itself establish a unique physical sector.

Selecting a Bell site highlights every bearing with a usable reported direction, beamwidth and frequency, even at locations with a number of bearings other than three; bearing colors repeat after three. Click a fan to emphasize it and show its bearing, frequency, reported and displayed beamwidth, and calculated and displayed radius. For overlapping fans, select a site and use its bearing buttons to choose a sector; these buttons are also keyboard accessible. TELUS non-directional records do not have sector fans.

Use **Find a licensed site** to search enabled TELUS and Bell records locally by reported location, site or cell ID, coordinates, or licensee. Search results show up to eight nearest matches. Select a result for its details and **View site in 3D**. The selected site has a map ring; **Show fans for selected site only** reduces overlap, and **Fan intensity** changes fill transparency without changing the calculation or the 5/12 display scale.

Each fan radius is an illustrative link-budget estimate using the urban macro (UMa) mean path-loss equations in [3GPP TR 38.901 v18.0.0, table 7.4.1-1](https://www.etsi.org/deliver/etsi_tr/138900_138999/138901/18.00.00_60/tr_138901v180000p.pdf), with the lowest reported TX frequency at each bearing. For visualization only, each fan is intentionally drawn at 5/12 of its original calculated radius to reduce clutter; the model estimate is unchanged, and selected-site details show both distances. The controls default to NLOS, an assumed 46 dBm EIRP and a −100 dBm received-power threshold; those values are planning assumptions, not published site parameters or 3GPP requirements. The calculation assumes a 25 m base station, 1.5 m receiver, 0 dBi receiver gain and no additional losses; it is limited to 10 m–5 km and 0.5–100 GHz. The scaled boresight radius is applied uniformly across the fan. There is no site-specific building or terrain modelling, shadow or fading margin, interference, load, penetration or directional antenna-pattern loss. It is neither measured coverage nor an RSRP/SINR or calibrated network prediction.

## Data and limitations

- TELUS locations use 783 records at 60 distinct coordinate pairs, filtered from the [ISED Terrestrial Spectrum Licence Site Data Extract](https://ised-isde.canada.ca/site/spectrum-management-system/en/spectrum-management-system-data/download-sms-data) dated 2026-11-03. The approximate Toronto-area bounding box is longitude -79.64 to -79.10 and latitude 43.58 to 43.85; it is not a municipal boundary. Counts are records and coordinate pairs, not verified physical sites or towers. All records in this selection are classified as indoor (`site_type=I`, `structure_type=O`); their structure-height field is not applicable as a tower height under [ISED's field definition](https://ised-isde.canada.ca/site/spectrum-management-system/en/spectrum-management-system-data/text-format-spectrum-licence-site-data-upload). The viewer therefore shows location markers and reported TX antenna heights, but no 3D tower for these records. Reported LTE, 5GNR and HSPA are ISED attributes, not measured coverage or confirmation of current service.
- Bell outdoor context contains 174,416 records at 1,481 coordinate pairs in the same bounding box and ISED extract, filtered to licensee `Bell Mobility Inc.` and `site_type=O`. Records are summarized by attributes at each coordinate. This includes rooftop, pole, tower and other outdoor structures; an orange marker does not verify TELUS service at that particular location. The [CRTC describes Bell and TELUS's shared radio access network](https://crtc.gc.ca/eng/archive/2025/2025-245.htm), but the licence extract does not establish the service relationship for individual sites. Location pairs and reported heights are not independently surveyed or confirmed current.
- For an outdoor, purpose-built tower (`site_type=O`, `structure_type=T`), a schematic lattice model appears at zoom 14 or closer only when all records at that coordinate have the same valid 1–600 m ISED structure height. In this snapshot 140 Bell coordinate pairs meet that strict rule. Rooftops, mixed structures and records with missing or conflicting heights remain map markers. Model shape is illustrative, its height is as reported rather than independently surveyed, and its base uses terrain elevation. The planning model uses its stated fixed base-station height rather than these reported structure heights.
- Rebuild with `python3 scripts/extract_telus_sites.py Site_Data_Extract_FX.zip dist/telus-sites.geojson --ised-date 2026-11-03` and `python3 scripts/extract_bell_outdoor.py Site_Data_Extract_FX.zip dist/bell-outdoor-sites.geojson --ised-date 2026-11-03`. The ISED ZIP used here has SHA-256 `b9a81941b0d13d821d2cd4242876204d5410f41cc4da20ebfc0ed715b307c0f3`; verify a new extract's date and checksum before rebuilding. The previous strict 30 m OSM proximity comparison yielded zero matches; ISED coordinates are displayed directly and do not imply an OSM match. The OSM PBF checksum is listed below.

- [OpenFreeMap](https://openfreemap.org/) provides on-demand OpenMapTiles vector tiles based on OpenStreetMap, including roads, transit, water, land use, labels, points of interest and building footprints where present in its schema and style. The map is not limited to the original downtown snapshot. OSM data © OpenStreetMap contributors, available under the [ODbL](https://www.openstreetmap.org/copyright); attribution is displayed on the map.
- OpenFreeMap's vector tile schema and style select, transform and generalize OSM features and attributes by zoom. They do not expose every OSM tag or feature.
- [Mapterhorn](https://mapterhorn.com/attribution) provides Terrarium-encoded digital elevation tiles. MapLibre drapes the base map over this terrain with 1× vertical exaggeration. Elevations are sampled terrain estimates, not surveyed ground or building heights; coverage, resolution and accuracy depend on the source dataset.
- At zoom 15 and closer, mapped roof shapes replace matching flat tile extrusions using Three.js; mapped flat roof colours are overlaid where available. Roofs use OSM height, direction, orientation and colour tags when present, with estimated roof heights when absent. The renderer supports gabled, skillion, hipped, pyramidal, dome, cone and onion shapes, including `pitched` and `shed` aliases; concave gabled and skillion footprints are supported. Flat and skillion roofs can preserve courtyards in mapped multipolygon relations. Other unsupported or invalid footprints and roof types fall back to the original flat extrusion. Matching uses ID suffixes observed in a Toronto tile and depends on the provider retaining compatible IDs. The Three.js layer also marks the selected feature.
- Trees come from the same BBBike Toronto extract: 54,879 `natural=tree` nodes and 5,113 estimated positions along mapped `natural=tree_row` ways. At overview zooms only unclustered tree points are shown; at zoom 15 and closer, individual trees are rendered in 3D using the elevation tiles. Row spacing defaults to 8 m when absent, and missing heights and crown sizes use illustrative defaults. These are not a tree census. From `ndt/`, rebuild the tree tiles with `uv run scripts/extract_trees.py Toronto.osm.pbf NEW_EMPTY_DIRECTORY --source "BBBike Toronto OSM extract 2026-10-31"` and place the resulting files in `dist/trees/`.
- At zoom 17 and closer, mapped `highway=street_lamp` and `amenity=bench` nodes from the same extract appear as simple terrain-aligned models. The extract has 29,015 lamps and 10,759 benches; the viewer shows at most 1,000 within 1.2 km of the map center. Model dimensions and bench orientation are illustrative, and a mapped point does not guarantee the feature still exists. From `ndt/`, rebuild with `uv run scripts/extract_street_detail.py Toronto.osm.pbf NEW_EMPTY_DIRECTORY --source "BBBike Toronto OSM extract 2026-10-31"` and place the resulting files in `dist/street-detail/`.
- Water color and fixed southeast lighting are visual treatments, not measured water conditions or sun position. Optional ground-draped building shadows approximate projected footprints, are limited to 1,500 polygons and cap building heights at 150 m. They do not account for terrain occlusion, building-to-building shadows, tree shadows, courtyards, or time of day; tile clipping and incomplete data may produce artifacts.
- Roof data is a fixed [BBBike Toronto OSM extract](https://download.bbbike.org/osm/bbbike/Toronto/) dated 2026-10-31; its PBF SHA-256 is `b8dc99b3b43de1542662c1479b8c567b121dbfc3207a1cd86be9786a323a1a81`. From `ndt/`, rebuild the roof subset from a downloaded PBF with `uv run scripts/extract_roofs.py Toronto.osm.pbf dist/toronto-roofs.json --source "BBBike Toronto OSM extract 2026-10-31"`. The extraction script installs its pinned osmium dependency into uv's cache; the application itself has no Python dependency.
- The application requires the external tile services at runtime. If map tiles are unavailable, the map cannot be used; if elevation tiles are unavailable, terrain is not verified. `dist/toronto.json` and `scripts/convert_osm.py` retain the earlier downtown snapshot and converter for reference, but the city-wide map does not use that snapshot.
- Three.js and OrbitControls are distributed under their included MIT license (`dist/vendor/LICENSE`); MapLibre GL JS uses the included BSD license (`dist/vendor/MAPLIBRE-LICENSE.txt`).

## Check

Node.js is needed for the JavaScript tests and syntax checks. Run `make test` for the OSM parsing, tile attributes, tree extraction and roof geometry tests, or `make check` for those tests and source syntax checks. Run `make help` to list the commands.

For the Playwright UI tests, install Node.js and run the following from the workspace root:

```sh
npm ci
npx playwright install chromium --only-shell
make test-ui
```

The browser suite starts a local server on port 5189 and checks search, network and layer controls, failure recovery, responsive layouts, keyboard use and automated WCAG A/AA rules. It substitutes a minimal map style and search responses; it does not verify live map tiles, terrain, or the external search service. To additionally run the network-dependent desktop, mobile and landscape map smoke tests, use `NDT_LIVE_UI=1 npm run test:ui -- live.spec.cjs`. Automated accessibility checks do not replace testing with assistive technology.

To run the same UI suite in other engines, install them with `npx playwright install firefox webkit`, then use `NDT_BROWSER=firefox npm run test:ui` or `NDT_BROWSER=webkit npm run test:ui`.

See [the benchmark](../docs/BENCHMARK.md) for earlier visual and performance observations and their comparison limits.
